# 18 — The sandbox can write the host's git-installed Pi packages

**What to build:** `~/.pi/agent/git/`, where Pi clones packages installed with
`pi install git:...`, must be read-only inside the sandbox. ADR 0002 holds Pi
packages read-only for this reason: "so that a bad turn cannot persist code
changes (extensions, Pi packages) into the host setup". Today only
`~/.pi/agent/extensions` gets a read-only sub-mount (npm packages have since
moved to the sandbox's own tree, ADR 0009). `git/` is reached through the
read-write agent-directory mount, so a sandboxed turn can edit code the host Pi
loads on its next start.

**Status:** resolved

- [x] The wrapper creates `$HOME/.pi/agent/git` on the host as the invoking user
      when it is absent, and always mounts it read-only at its own path. It is
      never listed as a missing optional mount.
- [x] `tests/safe-pi-wrapper-test.sh` covers the read-only mount, including on
      a host where the directory did not exist before the start.
- [x] Verified on this host: writing under `~/.pi/agent/git/` from
      `safe-pi --shell` fails with a read-only file system error.
- [x] The README's "What the sandbox sees" list says git-installed Pi packages
      are read-only in the sandbox, and that `pi install git:...` (and
      `update`/`remove` of a git package) does not work inside the sandbox.

## What is known

Found on 2026-10-10 while settling ticket 17:

- `~/.pi/agent/git/github.com/obra/superpowers` exists on the macOS host. It is
  not in `~/.pi/agent/settings.json`'s `packages`, so nothing loads it today. It
  has no `node_modules` and no native bindings.
- The wrapper's only read-only sub-mount for installed code is `add_mount
  "$PI_AGENT_DIR/extensions" ... ro` (`pi/.local/bin/safe-pi`). Since ticket 17
  the sandbox package tree is bound over `npm/`, and the host's `package.json`
  and `package-lock.json` are mounted read-only at a container-only path. There
  is no mount for `git/`; `safe-pi --dry-run` confirms it falls under the
  read-write agent-directory mount.
- Pi resolves a git source to `<agentDir>/git/<host>/<path>`. It writes there
  only to install a missing clone (`installGit`, which also writes
  `git/.gitignore`), to run `npm install` in a clone with missing dependencies
  (`repairMissingGitDependencies`), and on `pi install`/`update`/`remove`
  (Pi's `core/package-manager.js`). A start with every clone present writes
  nothing there.

## Decisions (triage, 2026-10-10)

- **Read-only, not a sandbox-owned tree.** A git package whose clone or
  dependencies are missing fails to install inside the sandbox; Pi reports it
  and the host Pi installs it on its next start. No loaded git package exists,
  and none carries native bindings, so ADR 0009's sandbox-owned tree is not
  warranted. Revisit if a git package with native bindings is ever declared.
- **The mount is a fixed point, not optional.** If `git/` were absent and only
  reported missing, a sandboxed `pi install git:...` would create it through the
  read-write agent-directory mount and persist a clone on the host. The wrapper
  therefore creates the directory first (as it already does for `npm/`, so the
  daemon does not create the mount point root-owned) and always mounts it
  read-only.

## Agent Brief

**Category:** bug
**Summary:** Hold the host's git-installed Pi packages read-only inside the
sandbox, even on a host that has none yet.

**Current behavior:**
`safe-pi` mounts the Pi agent directory read-write and adds read-only
sub-mounts for installed code, but none for `~/.pi/agent/git/`, where Pi clones
`git:` packages. A sandboxed turn can therefore modify, add, or remove a git
package's code, and the host Pi loads that code on its next start. This breaks
ADR 0002's rule that Pi packages are read-only in the sandbox. Confirmed with
`safe-pi --dry-run`: no mount targets `~/.pi/agent/git`.

**Desired behavior:**
- The sandbox sees `$HOME/.pi/agent/git` at its own path, read-only, on every
  start (`--shell`, `--prepare`, and normal starts alike, since they share the
  mounts).
- When the directory does not exist on the host, the wrapper creates it as the
  invoking user before starting the container, then mounts it read-only. It
  must not be created by the Docker daemon (root-owned), and it must not appear
  among the missing optional mounts.
- Inside the sandbox, any write under `~/.pi/agent/git/` fails with a read-only
  file system error. A git package that needs installing or dependency repair
  fails to install in the sandbox; this is accepted (see the ticket's
  Decisions), not worked around.
- The rest of the agent directory stays writable as today.

**Key interfaces:**
- The wrapper's mount contract: the list of container paths and modes it
  records and prints (the `contract_paths` set and the bind-mount arguments in
  `--dry-run` output). `~/.pi/agent/git` joins it as a read-only fixed point,
  beside the other always-mounted paths.
- The wrapper's "ensure required host mount points exist" step, which already
  pre-creates the agent, sessions, transpile-cache and npm directories.
- The wrapper test's mount assertions (`assert_log` on the
  `--mount type=bind,...,readonly` argument), as used for the extensions mount.
- The README's "What the sandbox sees" list and the paragraph noting that
  extensions are read-only in the sandbox.

**Acceptance criteria:**
- [x] `safe-pi --dry-run` shows `--mount type=bind,source=$HOME/.pi/agent/git,target=$HOME/.pi/agent/git,readonly`.
- [x] Starting the wrapper on a home with no `~/.pi/agent/git` leaves that
      directory existing and owned by the invoking user, mounts it read-only,
      and does not report it as missing.
- [x] The wrapper test covers both cases: directory present, and directory
      absent before the start.
- [x] On this host, `safe-pi --shell` then `touch ~/.pi/agent/git/x` fails with
      "Read-only file system", and `touch ~/.pi/agent/x` still succeeds (remove
      it afterwards).
- [x] The README says git-installed Pi packages are read-only in the sandbox and
      that installing, updating or removing a git package must be done from the
      host Pi.
- [x] `tests/run --full` ends with `FULL GATE: PASS`.

**Out of scope:**
- A sandbox-owned tree for git packages (ADR 0009 style) or converging git
  packages inside the sandbox.
- Changing how `~/.pi/agent/extensions` is mounted. It is still an optional
  mount, so a host without it has the same gap; that is a separate ticket if
  wanted.
- Loading or declaring `obra/superpowers` or any other git package.
- Amending ADR 0002 or ADR 0009: this ticket implements ADR 0002's existing
  read-only rule for Pi packages.
