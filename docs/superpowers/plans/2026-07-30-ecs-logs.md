# ECS Logs Helper Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add executable `general/bin/ecs-logs` that discovers an ECS service's CloudWatch log group and delegates log following to AWS CLI.

**Architecture:** A Bash wrapper validates cluster/service arguments, calls `aws ecs describe-services` and `aws ecs describe-task-definition`, then resolves exactly one unique `awslogs` group. It `exec`s `aws logs tail --follow`, passing remaining arguments unchanged. AWS CLI configuration and environment variables provide profile, region, credentials, and other AWS context.

**Tech Stack:** Bash, AWS CLI v2 command interface, temporary mock executable for tests.

## Global Constraints

- Use only AWS CLI beneath wrapper; do not add SDK, `jq`, or other runtime dependency.
- Script path must be `general/bin/ecs-logs` and be executable.
- Required interface: `ecs-logs <cluster> <service> [aws logs tail arguments...]`.
- AWS profile/region come from normal AWS CLI configuration or environment variables; extra arguments go only to `aws logs tail`.
- Missing log group must fail clearly; multiple distinct groups must fail and list groups.
- Tests must not contact AWS.

**Files:**

**Interfaces:**

- [ ] **Step 1: Write mock-driven failing tests**

Create a Bash test script with a temporary `aws` mock and isolated `PATH`. Mock behavior is selected by `$MOCK_CASE`; each argument is recorded as one NUL-delimited value in `$AWS_CALLS` so passthrough assertions preserve boundaries:

```bash
#!/usr/bin/env bash
set -euo pipefail

script_dir=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)
tmp_dir=$(mktemp -d)
trap 'rm -rf "$tmp_dir"' EXIT
mkdir "$tmp_dir/bin"
cat > "$tmp_dir/bin/aws" <<'MOCK'
#!/usr/bin/env bash
printf '%s\\0' "$@" >> "$AWS_CALLS"
case "$MOCK_CASE:$1 $2 $3" in
  success:*'ecs describe-services'*) printf '%s\\n' arn:task-definition/1 ;;
  success:*'ecs describe-task-definition'*) printf '%s\\n' /ecs/app ;;
  success:*'logs tail'*) exit 0 ;;
  not-found:*'ecs describe-services'*) printf '%s\\n' None ;;
  no-group:*'ecs describe-services'*) printf '%s\\n' arn:task-definition/1 ;;
  no-group:*'ecs describe-task-definition'*) printf '\\n' ;;
  multiple:*'ecs describe-services'*) printf '%s\\n' arn:task-definition/1 ;;
  multiple:*'ecs describe-task-definition'*) printf '%s\\n' /ecs/a /ecs/b ;;
  *) printf 'unexpected mock call\\n' >&2; exit 99 ;;
esac
MOCK
chmod +x "$tmp_dir/bin/aws"
export AWS_CALLS="$tmp_dir/aws.calls"
export PATH="$tmp_dir/bin:$PATH"

assert_contains() { grep -F -- "$2" "$1" >/dev/null || { printf 'missing %s\\n' "$2" >&2; return 1; }; }
run_case() { MOCK_CASE=$1 "$script_dir/ecs-logs" "${@:2}"; }

run_case success cluster-a service-a --since 10m --format short
assert_contains "$AWS_CALLS" '/ecs/app'
assert_contains "$AWS_CALLS" '--follow'
assert_contains "$AWS_CALLS" '--since'
assert_contains "$AWS_CALLS" '10m'
assert_contains "$AWS_CALLS" '--format'
assert_contains "$AWS_CALLS" 'short'

if run_case missing cluster-a >/tmp/ecs-logs-test.out 2>&1; then exit 1; fi
assert_contains /tmp/ecs-logs-test.out 'Usage:'
if run_case not-found cluster-a service-a >/tmp/ecs-logs-test.out 2>&1; then exit 1; fi
assert_contains /tmp/ecs-logs-test.out 'service not found'
if run_case no-group cluster-a service-a >/tmp/ecs-logs-test.out 2>&1; then exit 1; fi
assert_contains /tmp/ecs-logs-test.out 'no awslogs group'
if run_case multiple cluster-a service-a >/tmp/ecs-logs-test.out 2>&1; then exit 1; fi
assert_contains /tmp/ecs-logs-test.out '/ecs/a'
assert_contains /tmp/ecs-logs-test.out '/ecs/b'
assert_contains /tmp/ecs-logs-test.out 'multiple'
printf 'PASS\\n'
```

The test must additionally assert discovery argument values (`cluster-a`, `service-a`, and task definition ARN) by decoding `$AWS_CALLS`; do not reduce coverage to exit status only. The five cases are: successful tail and exact passthrough; missing positional argument; service response `None`; empty task-definition group output; and two distinct groups.

### Task 2: Implement ECS log tail wrapper

**Files:**

- Create: `general/bin/ecs-logs`

**Interfaces:**

- Consumes: cluster and service positional arguments; remaining arguments as an array.
- Produces: process replacement with `aws logs tail <group> --follow <extra args...>` and clear non-zero failures.

- [ ] **Step 1: Implement strict Bash wrapper**

Write executable Bash with this structure:

```bash
#!/usr/bin/env bash
set -euo pipefail

if (( $# < 2 )); then
  printf 'Usage: ecs-logs <cluster> <service> [aws logs tail arguments...]\n' >&2
  exit 2
fi

if ! command -v aws >/dev/null 2>&1; then
  printf 'Error: aws CLI not found\n' >&2
  exit 127
fi

cluster=$1
service=$2
shift 2
```

Resolve task definition with `aws ecs describe-services --cluster "$cluster" --services "$service" --query 'services[0].taskDefinition' --output text`. Capture stderr naturally. Treat empty output or `None` as `service not found` and exit non-zero.

Resolve groups with `aws ecs describe-task-definition --task-definition "$task_definition" --query 'taskDefinition.containerDefinitions[].logConfiguration[?logDriver==\`awslogs\`].options."awslogs-group"' --output text`. Treat missing output and`None` output as `no awslogs group configured for service` and exit non-zero.

Normalize CLI text output line-by-line: ignore blank/`None` lines, remove duplicates, and collect group names in a Bash array. Do not word-split group names; use `mapfile`/`readarray` or an equivalent line-preserving loop.

If array length exceeds one, print `Error: multiple awslogs groups found:` followed by each group and exit non-zero. Otherwise execute exactly:

```bash
exec aws logs tail "${groups[0]}" --follow "$@"
```

Keep AWS context in environment/configuration. Do not attempt to parse or forward `--profile`/`--region` from tail arguments.
